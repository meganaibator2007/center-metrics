# center-metrics — прототип интерфейса

Кликабельный прототип системы учёта показателей деятельности центра на HTML и CSS, в фирменном стиле Финансового университета. Бэкенда нет: формы и кнопки ведут на следующие экраны, данные вымышленные.

## Как открыть

Дважды кликнуть `index.html`. Откроется карта экранов, оттуда можно перейти куда угодно.

Сервер не нужен, интернет тоже: шрифты лежат локально в `static/fonts`. В настоящей системе эти файлы будет отдавать само Spring Boot-приложение (запуск через Docker Compose, задача T-05). Отдельный веб-сервер для HTML не нужен.

## Запуск на другом компьютере

Перенести папку проекта: архивом `center-metrics-prototype.zip` (флешка, облако, «Избранное» в Telegram) или потом из репозитория через `git clone`.

### Способ 1. Ничего не устанавливать (подходит для компьютера преподавателя)

1. Распаковать архив.
2. Открыть папку и дважды кликнуть `index.html`.

Работает на Windows, macOS и Linux в любом современном браузере. Не нужны интернет и права администратора.

### Способ 2. Linux / Firefox: маленький локальный сервер

Firefox не подгружает шрифты из соседних папок, когда страница открыта двойным кликом (адрес `file://...`). Тогда вместо фирменных шрифтов будет обычный. Чтобы этого не было, сайт запускают через встроенный в Python сервер: на Fedora Python уже стоит, ничего ставить не нужно.

1. Открыть терминал в папке проекта: в «Файлах» правой кнопкой по папке → «Открыть в терминале».
2. Выполнить:
   ```bash
   python3 -m http.server 8000
   ```
3. Открыть в браузере http://localhost:8000

Остановить: Ctrl + C в терминале.

Настоящую систему (Spring Boot + PostgreSQL) будет поднимать Docker Compose, это задача T-05.

## Структура

Папки повторяют будущий Spring Boot (`src/main/resources/templates` и `static`), пакеты те же, что в техсоглашениях:

```
index.html                    карта экранов (только для показа)
static/css/main.css           весь стиль: токены брендбука + компоненты (T-07, T-20)
static/img/                   логотип (цветной и белый), знак, паттерн «паруса»
static/fonts/                 Golos Text и Open Sans (WOFF2) + лицензии
templates/user/login.html     вход (T-26)
templates/user/list.html      пользователи (T-31)
templates/user/form.html      новый пользователь (US-09)
templates/entry/cabinet.html  кабинет преподавателя (T-47)
templates/entry/form.html     ввод данных (T-50, T-51)
templates/entry/submit.html   отправка отчёта, блок без обязательных (US-20)
templates/indicator/list.html справочник показателей (T-36)
templates/indicator/form.html форма показателя (T-37)
templates/period/list.html    отчётные периоды (US-13)
templates/report/teacher.html       отчёт преподавателя + печать (T-67)
templates/report/teacher-admin.html тот же отчёт глазами админа
templates/report/summary.html       сводный отчёт и рейтинг (T-69)
templates/report/control.html       контроль сдачи (T-74), стартовая страница админа
templates/error/403|404|500.html    страницы ошибок (T-07)
templates/common/stub.html          заглушка «в разработке» с планом по спринтам
```

Заглушка одна на все функции. Нужный текст выбирается якорем: `stub.html#export`, `#review`, `#history`, `#dashboard`, `#fields`, `#archive`, `#close-period`, `#password`, `#user-edit`, `#help`, `#privacy`. Работает на чистом CSS (`:target`).

## Правила, которые соблюдены

- Ни одного `<script>` и ни одного `style="..."`. Всё оформление лежит в `main.css`.
- У каждого поля есть `<label>`. Проверки сделаны средствами HTML: `required`, `min`, `pattern`, даты в пределах периода.
- Фильтры и сортировка работают через параметры в адресе (`?period=...&sort=...`).
- Подтверждение отправки отчёта вынесено на отдельную страницу.
- Есть печатная версия отчёта (Ctrl + P) и адаптив под телефон.

## Перенос в Thymeleaf (T-07 и дальше)

1. Шапку и футер вынести в `templates/fragments/layout.html` (`th:fragment`). Сейчас они скопированы в каждый файл.
2. Ссылки `../../static/...` заменить на `th:href="@{/css/main.css}"`. Ссылки между страницами заменить на `th:href="@{/...}"`.
3. В формах указать `th:action`, `method="post"`, `th:object`/`th:field`, а под полями `th:errors`. В прототипе у полей нет `name` специально, чтобы при показе ничего не попадало в адресную строку. Подсказки оставлены HTML-комментариями прямо в шаблонах.
4. Демо-строки таблиц заменить на `th:each`, бейджи статусов собирать через `th:classappend`.
5. Папки `static/css`, `static/img`, `static/fonts` переложить в `src/main/resources/static` как есть.

## План показа на 5 минут

1. **Карта экранов** (`index.html`, 30 с): что за система, две роли, 16 из 20 экранов готовы, остальное — заглушки с планом по спринтам.
2. **Вход** (20 с): фирменный стиль, паттерн, демо-кнопки ролей.
3. **Кабинет преподавателя** (1 мин): сумма баллов и заполненность. Навести на «40 ⓘ» у статьи ВАК: 5 × 10 = 50, но балл ограничен максимумом 40 (BR-01, BR-02). Красная строка — незаполненный обязательный показатель.
4. **Отправить на проверку** (30 с): система не даёт отправить без обязательного показателя (BR-08). Дальше «Заполнить показатель».
5. **Ввод данных** (40 с): поля зависят от показателя (JSONB-схема), справа формула. Нажать «Сохранить» с пустыми полями — браузер не пропустит.
6. **Мой отчёт** (20 с): группировка по разделам, Ctrl + P — печатная версия с подписями.
7. **Выйти → Как администратор → Контроль сдачи** (40 с): кто сдал и кто нет, сначала проблемные.
8. **Сводный отчёт** (30 с): рейтинг, фильтры, сортировка. Рейтинг видит только админ (BR-07). «Скачать PDF» — заглушка спринта 5.
9. **Показатели и Периоды** (30 с): архив вместо удаления (BR-11), периоды одного типа не пересекаются (BR-06).

Честно сказать на защите: показатели — примеры, реальный перечень от заказчика ещё не получен (T-21). Данные вымышленные. Логика (расчёт, права, сохранение) появится вместе с бэкендом.
