# База данных

PostgreSQL 16. Схему меняют только миграции Flyway в `app/src/main/resources/db/migration`, Hibernate её только проверяет (`ddl-auto: validate`). Общие правила миграций — в [архитектуре](ARCHITECTURE.md#база-и-миграции).

10 таблиц в шести миграциях, у каждого пакета свои таблицы с префиксом:

| Миграция | Пакет | Таблицы |
|---|---|---|
| `V100__user_create_tables.sql` | user | `usr_user` |
| `V200__indicator_create_tables.sql` | indicator | `ind_category`, `ind_indicator` |
| `V300__period_create_tables.sql` | period | `per_period` |
| `V400__entry_create_tables.sql` | entry | `ent_entry`, `ent_attachment`, `ent_period_lock` |
| `V500__scoring_create_tables.sql` | scoring | `scr_score` |
| `V600__report_create_tables.sql` | report | `rep_report`, `rep_report_history` |

## Главная идея: журнал по датам

Запись преподавателя не привязана к периоду. У неё есть дата — когда это произошло: публикация, окончание курса, выступление. Отчёт за любой период собирается из записей, дата которых входит в этот период.

Статья от 15.10.2026 сама попадает в отчёт за октябрь 2026, за 1 семестр 2026/27 и за учебный год, если такие периоды есть. Вносить её дважды не нужно, исправлять — тоже в одном месте.

- Периоды одного типа не пересекаются, разных типов могут (семестр и октябрь внутри него).
- Кабинет без `periodId` показывает открытый период, в который попадает сегодняшняя дата; если таких несколько — самый длинный; если ни одного — открытый период с самой поздней датой окончания.
- Баллы считаются отдельно для каждого периода, у каждого свой максимум по показателю.
- Отчёт отправлен — записи с датой внутри его периода менять нельзя, пока отчёт не вернут на доработку.

## Общие правила

| Что | Как сделано |
|---|---|
| Первичный ключ | `id BIGINT GENERATED BY DEFAULT AS IDENTITY`, в JPA `@GeneratedValue(strategy = IDENTITY)` |
| Перечисления (роль, статус, тип) | `VARCHAR` + `CHECK (... IN (...))`, в JPA `@Enumerated(EnumType.STRING)` |
| Даты и моменты | `DATE` → `LocalDate`, `TIMESTAMPTZ` → `Instant` |
| Баллы, коэффициенты, значения | `NUMERIC` → `BigDecimal` |
| Поля формы | `JSONB`, в JPA `@JdbcTypeCode(SqlTypes.JSON)` |
| Связи между пакетами | только колонка с ID (`teacher_id`, `period_id`, `indicator_id`), без внешнего ключа; существование проверяет сервис другого пакета |
| Связи внутри пакета | обычный внешний ключ: `ind_indicator → ind_category`, `ent_attachment → ent_entry`, `rep_report_history → rep_report` |
| Удаление | пользователи блокируются, показатели уходят в архив, периоды закрываются; удаляются только записи преподавателя, их файлы — каскадом |
| `created_at`, `updated_at` | заполняет Hibernate: `@CreationTimestamp`, `@UpdateTimestamp` |
| Имена ограничений | `таблица_что_тип`: `_fk`, `_uk`, `_ck`, `_ex`, `_idx`. Имя видно в тексте ошибки базы |

## Таблицы

### usr_user — пользователи

Преподаватель — это пользователь с ролью `TEACHER`, отдельной таблицы нет.

| Колонка | Тип | Что это |
|---|---|---|
| `id` | BIGINT | |
| `login` | VARCHAR(50), уникальный | `a-z 0-9 . -`, 3–50 символов, только нижний регистр |
| `password_hash` | VARCHAR(100) | хеш BCrypt |
| `last_name`, `first_name` | VARCHAR(100) | |
| `middle_name` | VARCHAR(100), null | |
| `role` | VARCHAR(20) | `TEACHER` или `ADMIN` |
| `department` | VARCHAR(150), null | кафедра строкой; обязательна только у преподавателя |
| `position` | VARCHAR(100), null | должность |
| `active` | BOOLEAN | false — заблокирован |
| `must_change_password` | BOOLEAN | пароль временный: выдан при создании или сбросе |
| `last_login_at` | TIMESTAMPTZ, null | «Последний вход» |

### ind_category — разделы показателей

`id`, `name` (уникальное), `sort_order` — порядок вкладок и групп.

### ind_indicator — показатели и правило начисления баллов

| Колонка | Тип | Что это |
|---|---|---|
| `category_id` | BIGINT, FK → `ind_category` | |
| `name` | VARCHAR(255) | уникально среди действующих в категории, без учёта регистра |
| `description` | VARCHAR(1000), null | пояснение для преподавателей |
| `unit` | VARCHAR(20) | шт., чел., ч, п. л., группа |
| `scoring_method` | VARCHAR(20) | `PER_UNIT` — сумма значений × коэффициент; `FIXED` — число записей × коэффициент |
| `coefficient` | NUMERIC(10,3) | больше 0 |
| `max_score` | NUMERIC(10,2) | больше 0, потолок баллов за период |
| `required` | BOOLEAN | без него отчёт не отправить |
| `attachment_required` | BOOLEAN | без файла по нему отчёт не отправить |
| `fields` | JSONB | поля формы: `[{key, label, type, required, options}]`, тип TEXT, NUMBER, DATE, URL, SELECT |
| `sort_order` | INTEGER | |
| `archived`, `archived_at` | BOOLEAN, TIMESTAMPTZ | архив вместо удаления |

### per_period — отчётные периоды

| Колонка | Тип | Что это |
|---|---|---|
| `name` | VARCHAR(100) | «1 семестр 2026/27» |
| `type` | VARCHAR(20) | `MONTH`, `QUARTER`, `SEMESTER`, `YEAR` |
| `start_date`, `end_date` | DATE | граничные дни входят в период |
| `status` | VARCHAR(20) | `OPEN` или `CLOSED` |
| `closed_at` | TIMESTAMPTZ, null | заполнено тогда и только тогда, когда период закрыт |

Ограничение `per_period_no_overlap_ex` (`EXCLUDE`) не даёт двум периодам одного типа пересечься даже при одновременных запросах. Ему нужно расширение `btree_gist` — стандартное, есть в образе `postgres:16-alpine` и в Testcontainers.

### ent_entry — журнал достижений преподавателя

| Колонка | Тип | Что это |
|---|---|---|
| `teacher_id` | BIGINT, ID → `usr_user` | из сессии, не из запроса |
| `indicator_id` | BIGINT, ID → `ind_indicator` | |
| `event_date` | DATE | когда это произошло; определяет, в какие периоды попадает запись |
| `value` | NUMERIC(12,2) | больше 0; для способа `FIXED` сервис пишет 1 |
| `proof_url` | VARCHAR(500), null | ссылка на подтверждающий материал |
| `fields` | JSONB | значения полей формы `{"key": значение}` |
| `comment` | VARCHAR(1000), null | |

### ent_attachment — подтверждающие файлы

Сам файл лежит на диске вне `static/` (папка `APP_STORAGE_DIR`), в базе — сведения о нём. `entry_id` (FK, удаляется вместе с записью), `original_name`, `content_type` (только PDF, JPEG, PNG), `size_bytes` (до 10 МБ), `storage_key` (имя на диске, UUID, уникальное), `uploaded_at`.

### ent_period_lock — блокировка после отправки отчёта

`teacher_id`, `period_id` (вместе уникальны), `start_date`, `end_date`, `locked_at`. Строку добавляет слушатель `ReportSubmitted`, удаляет — слушатель `ReportReturned`. Даты периода копируются сюда, чтобы проверка «можно ли менять запись» была одним запросом: есть ли блокировка этого преподавателя, в даты которой попадает `event_date`. Своя таблица нужна, потому что `entry` не может обращаться к `report`: был бы цикл.

### scr_score — баллы

Одна строка — итог по показателю у преподавателя за период, по записям с датой внутри периода. Нет записей — нет строки.

| Колонка | Тип | Что это |
|---|---|---|
| `teacher_id`, `period_id`, `indicator_id` | BIGINT, вместе уникальны | |
| `entry_count` | INTEGER | больше 0 |
| `total_value` | NUMERIC(14,2) | сумма значений |
| `scoring_method`, `coefficient`, `max_score` | как в `ind_indicator` | копия правила на момент расчёта |
| `score` | NUMERIC(10,2) | от 0 до `max_score` (CHECK) |
| `calculated_at` | TIMESTAMPTZ | |

`PER_UNIT`: min(total_value × coefficient, max_score); `FIXED`: min(entry_count × coefficient, max_score); округление до 0,01. Пересчёт идёт в той же транзакции, что и сохранение или удаление записи, для всех открытых периодов, в которые попадает её дата (старая и новая, если дату поменяли). Правило копируется в строку, поэтому баллы закрытого периода не меняются, даже если админ потом поправит показатель.

### rep_report — статус отчёта

Отчёт не хранит записи: его содержимое — записи журнала с датой в периоде и баллы из `scr_score`. Строка появляется при первой отправке, без неё отчёт — черновик.

`teacher_id` и `period_id` (вместе уникальны), `status` (`DRAFT`, `SUBMITTED`, `ACCEPTED`, `RETURNED`), `submitted_at` (обязательно для всех статусов, кроме черновика), `reviewed_at`, `reviewed_by`, `return_comment` (обязателен при `RETURNED`).

### rep_report_history — история статусов

`report_id` (FK), `status`, `comment`, `changed_by`, `changed_at`. Строки только добавляются: если отчёт возвращали дважды, оба комментария сохранятся.

## Индексы

| Индекс | Зачем |
|---|---|
| `ent_entry (teacher_id, event_date)` | журнал, кабинет и отчёт преподавателя за даты периода |
| `ent_entry (event_date, indicator_id)` | контроль сдачи, сводный отчёт, статистика по показателям |
| `scr_score (teacher_id, period_id, indicator_id)`, уникальный | кабинет и отчёт преподавателя, пересчёт одной строки |
| `scr_score (period_id, teacher_id)` | сводный отчёт, рейтинг, дашборд |
| `rep_report (period_id, status)` | контроль сдачи с вкладками по статусу |
| `ind_indicator (category_id, lower(name))`, уникальный частичный | нет двух действующих показателей с одним названием |
| `per_period` EXCLUDE | периоды одного типа не пересекаются |

Всего 16 индексов, не считая первичных ключей.

## Что проверено

Миграции накатаны через Flyway 12.4 на PostgreSQL 16.15, 54 проверки из 54:

- ограничения отклоняют плохие данные: преподаватель без кафедры, логин с заглавной буквой, коэффициент 0, пересечение семестров, запись без даты, файл 11 МБ или GIF, балл больше максимума, второй отчёт за период, возврат без комментария;
- запись от 13.10 попадает и в отчёт за октябрь, и в отчёт за семестр без повторного ввода;
- блокировка после отправки отчёта находит запись одним запросом по датам;
- файлы удаляются вместе с записью;
- без `out-of-order: true` новая `V101` после применённой `V600` не накатывается, с ним — накатывается.

## Что ещё решить

- Первый администратор не создаётся миграцией (репозиторий публичный): бэкенд создаёт его при старте из `ADMIN_LOGIN` и `ADMIN_PASSWORD`, если админов нет.
- Тестовые данные — отдельные миграции в `db/seed`, только для профиля `dev`.
- Колонки `scoring_method`, `attachment_required`, тип поля SELECT и `proof_url` пришли из сверки с Проект.docx и ещё не внесены в контракт API.
