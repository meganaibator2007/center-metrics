# Контракт API

> Эндпоинты пока не реализованы. Ниже указано то, что запланировано.

Основание — ТЗ «Система учёта показателей эффективности». Все адреса API начинаются с `/api`. Формат данных: JSON, ошибки: `ProblemDetail`.
Поля запросов и ответов описаны в [openapi.yaml](../app/src/main/resources/static/openapi.yaml). После запуска сервера их можно смотреть в Swagger UI: http://localhost:8080/swagger-ui.html. Меняем запрос или ответ — правим оба файла.
Для всех адресов, кроме входа, получения CSRF-cookie и проверки сервера, нужна сессия.

Запросы, меняющие данные, включая `POST /api/auth/login`, требуют CSRF-токен. Перед входом клиент вызывает `GET /api/auth/csrf`, получает токен в cookie и передаёт его в заголовке запроса.

Роли: **сотрудник** (`EMPLOYEE`), **РОП** (`REVIEWER`, в своей области), **директор** (`DIRECTOR`), **админ** (`ADMIN`, суперадминистратор). У человека их может быть несколько. Админ не заменяет директора при утверждении.

## Вход и система

| Метод | Адрес | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/auth/csrf` | все | Выдача CSRF-cookie перед входом |
| POST | `/api/auth/login` | все | Вход |
| POST | `/api/auth/logout` | вошедшие | Выход |
| GET | `/api/auth/me` | вошедшие | Текущий пользователь |
| POST | `/api/auth/password` | вошедшие | Смена своего пароля |
| GET | `/api/health` | все | Проверка сервера |

## Показатели

Правка показателя создаёт новую редакцию, утверждённые результаты остаются на своей. К периоду относится редакция, действующая на дату его начала.

| Метод | Адрес | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/indicators?category=&evaluationType=&archived=` | вошедшие | Справочник показателей |
| POST | `/api/indicators` | админ | Создание показателя |
| GET | `/api/indicators/{id}` | вошедшие | Карточка показателя |
| PUT | `/api/indicators/{id}` | админ | Новая редакция показателя |
| POST | `/api/indicators/{id}/archive` | админ | Перенос в архив и возврат |
| GET | `/api/indicators/{id}/versions` | вошедшие | Редакции показателя |

## Отчётные периоды

Достижение относится ровно к одному периоду. Периоды одного календарного типа не пересекаются, разных типов и произвольные могут.

| Метод | Адрес | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/periods` | вошедшие | Список периодов |
| GET | `/api/periods/current` | вошедшие | Текущий период |
| POST | `/api/periods` | админ | Создание периода |
| POST | `/api/periods/{id}/close` | админ | Закрытие периода |
| POST | `/api/periods/{id}/reopen` | директор | Переоткрытие периода |

## Достижения

Маршрут: `DRAFT` → `ON_REVIEW` → `REVIEWED` → `APPROVED`. С проверки можно вернуть (`RETURNED`) или отклонить (`REJECTED`), утверждённое директор отправляет на пересмотр (`REVISION`). В официальный итог входит только утверждённое. Участник достижения не может его проверять и утверждать. Очередь директора (`scope=approval`) — `REVIEWED`, которые он утверждает, и `ON_REVIEW` с `reviewer` = DIRECTOR, которые он сначала проверяет.

| Метод | Адрес | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/achievements?scope=&status=&periodId=&category=&indicatorId=&userId=&q=` | вошедшие, по области доступа | Реестр достижений |
| POST | `/api/achievements` | сотрудник; за другого — админ или полномочие ENTER_FOR_OTHERS | Создание черновика |
| POST | `/api/achievements/check-duplicates` | вошедшие | Поиск повторов до сохранения |
| GET | `/api/achievements/{id}` | вошедшие, по области доступа | Карточка достижения |
| PUT | `/api/achievements/{id}` | заявитель или кто ввёл за него | Изменение |
| DELETE | `/api/achievements/{id}` | заявитель или кто ввёл за него | Удаление черновика |
| POST | `/api/achievements/{id}/evidence` | заявитель или кто ввёл за него | Добавление подтверждения |
| GET | `/api/achievements/{id}/evidence/{evidenceId}/file` | вошедшие, по области доступа | Скачивание файла |
| DELETE | `/api/achievements/{id}/evidence/{evidenceId}` | заявитель или кто ввёл за него | Снятие подтверждения |
| POST | `/api/achievements/{id}/submit` | заявитель или кто ввёл за него | Отправка на проверку |
| POST | `/api/achievements/{id}/review` | РОП своей области; директор, если `reviewer` = DIRECTOR | Проверка пройдена |
| POST | `/api/achievements/{id}/return` | РОП своей области, директор | Возврат на доработку |
| POST | `/api/achievements/{id}/reject` | РОП своей области, директор | Отклонение |
| POST | `/api/achievements/{id}/approve` | директор | Утверждение |
| POST | `/api/achievements/{id}/revision` | директор | Отправка на пересмотр |
| POST | `/api/achievements/{id}/join` | сотрудник своей категории | Присоединение соавтором |

## Целевые показатели РОП

Значение уникально по редакции показателя, периоду и программе. Проверку данных и итоговое решение директор фиксирует отдельно. Утверждённое значение исправляется новой версией.

| Метод | Адрес | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/measurements?periodId=&programId=` | админ, директор; РОП — своя область | Значения |
| POST | `/api/measurements` | админ; РОП — своя область | Внесение значения |
| PUT | `/api/measurements/{id}` | админ; РОП — своя область | Изменение значения |
| POST | `/api/measurements/{id}/submit` | админ; РОП — своя область | Отправка директору |
| POST | `/api/measurements/{id}/review` | директор | Проверка данных |
| POST | `/api/measurements/{id}/approve` | директор | Утверждение |
| POST | `/api/measurements/{id}/return` | директор | Возврат |
| POST | `/api/measurements/{id}/reject` | директор | Отклонение |
| POST | `/api/measurements/{id}/revision` | директор | Исправление утверждённого значения |

## Баллы и дашборды

Расчёт только на сервере. На экранах утверждённые и предварительные значения идут отдельно.

| Метод | Адрес | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/scores/my?periodId=` | вошедшие | Мои баллы |
| GET | `/api/scores/users/{id}?periodId=` | сам сотрудник, админ, директор; РОП — своя область | Баллы сотрудника |
| GET | `/api/dashboard/director?periodId=` | директор, админ; РОП — своя область | Сводный дашборд |

## Отчёты

Первый этап — выгрузки XLSX. Настраиваемые шаблоны и PDF относятся ко второму этапу.

| Метод | Адрес | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/reports/{type}.xlsx?periodId=&userId=&category=&programId=&indicatorId=&status=` | вошедшие, по области доступа; `individual` — свой, остальные — директор, админ, РОП своей области | Выгрузка отчёта |

## Журнал и импорт

Импорт идёт в два шага: файл проверяется и ничего не меняет, потом загрузка подтверждается. Утверждённые результаты импорт не перезаписывает.

| Метод | Адрес | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/audit?objectType=&objectId=&page=&size=` | админ, директор | Журнал аудита |
| GET | `/api/imports` | админ; РОП с полномочием IMPORT | История загрузок |
| POST | `/api/imports` | админ; РОП с полномочием IMPORT — своя область | Загрузка и проверка файла |
| POST | `/api/imports/{id}/apply` | админ; РОП с полномочием IMPORT — своя область | Подтверждение загрузки |
| GET | `/api/imports/templates/{type}` | админ; РОП с полномочием IMPORT | Шаблон XLSX |
